# 企业级架构设计

## 目标

读取工程量清单与计价表，基于项目特征、工程量、计量单位、企业价格规则和后续可接入的定额/材料/历史报价库，自动计算综合单价与合价，并给出可追溯的取价依据。

## 分层架构

```text
src/boq_pricing
  domain/          领域模型：清单项、项目特征、取价结果、校验问题
  application/     应用服务：批量处理流程编排
  infrastructure/  Excel 读取/写入、JSON 规则库
  pricing/         取价匹配与计算引擎
  validation/      企业级质量校验
```

## 核心流程

1. Excel 表格识别：定位包含 `项目名称`、`项目特征`、`工程量`、`综合单价/单价`、`合价` 的表。
2. 清单标准化：将不同 sheet 的字段统一为 `BillItem`。
3. 项目特征解析：将多行自然语言拆成结构化指标，如 `桩型`、`桩长度`、`混凝土种类与强度等级`。
4. 取价规则匹配：按项目名称、单位、项目特征条件评分匹配。
5. 计算：`合价 = 工程量 * 综合单价`。
6. 校验：缺单价、缺工程量、单位不一致、无匹配规则、合价误差等。
7. 输出：生成结果 Excel 和 JSON 审计记录。

## 性能设计

- Excel 读取只遍历有效 sheet 和有效行，避免整簿复杂对象扫描。
- 表头识别基于别名字典，避免每个项目定制代码。
- 价格规则在加载时预编译为内存对象，批量处理时复用。
- 匹配采用“候选过滤 + 条件评分”，后续可升级为索引：
  - `item_name_keyword -> rules`
  - `unit -> rules`
  - `feature_key -> rules`
- 输出审计信息与计算结果分离，便于大批量异步任务、消息队列和数据库落库。

## 企业扩展点

- `PriceRuleRepository` 可替换为数据库、Redis 缓存或规则服务。
- `FeatureParser` 可接入大模型，仅负责结构化抽取，不直接决定价格。
- `PricingEngine` 可接入定额消耗量、材料信息价、人工机械费、地区系数。
- `ExcelBillReader` 可增加 PDF/OCR 输入适配器。
- `PricingApplicationService` 可由 CLI、API、任务队列或 Web 管理端复用。

## MySQL 关系模型

当前 MySQL 模型已经拆为规则主表、规则条件表、价格组成表、材料价格表、计价批次表和计价结果表。详见 [data_model.md](data_model.md)。

设计原则是“主数据关系化、复杂原文可审计保留”：

- 规则主数据用列保存，便于索引和权限控制。
- 项目特征条件用明细表保存，便于扩展匹配算法。
- 原始特征和审计结果继续保留 JSON，便于回放和问题定位。
- `tenant_code`、`region_code`、`specialty`、`cost_category` 作为企业扩展维度。

## 审计要求

每一条计价结果保留：

- 来源 sheet
- 来源行号
- 原始项目特征
- 解析后的特征指标
- 匹配的规则 ID
- 规则版本
- 综合单价
- 合价
- 校验问题
